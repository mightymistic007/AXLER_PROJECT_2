
# Project Rules

## Git Commits
- Always use simple, human-readable language for commit messages.
- Avoid overly technical jargon or highly structured formats (like `feat(scope): ...`) unless explicitly requested.
- Focus on clearly explaining the change in plain, easy-to-understand words.

## Communication Style
- Keep responses extremely short and concise.
- Use simple, short words.
- Avoid long explanations.
